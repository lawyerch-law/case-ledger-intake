# 金山-律师案件管理录入技能（case-ledger-intake）

律师个人案件台账（金山文档多维表 .dbt）**分阶段对话式录入**技能。律师把"脑子里的案情"用大白话讲出来，AI 自动解析成台账结构化字段并写回金山多维表，覆盖 7 阶段（委托/立案/开庭/保全/判决/执行/结案）。

> 输出为律师工作草稿，非法律意见。

## 这是什么

- **录入为主**：先定阶段 → 只追问该阶段必填字段（每轮 ≤2 问）→ 推断值标注确认 → 写回台账
- **时效推算**：自动推算诉讼时效截止日并提示中断风险（民法典 188/195 条）
- **查漏补缺**：对照阶段视图白名单暴露"该做没做"（委托合同/授权书/收费/时效/主体材料）
- **极简交互**：单表输出 + 末尾附台账链接，可点击跳转核对

## 前置条件

| 项 | 要求 |
|---|---|
| 平台 | WorkBuddy（支持技能系统） |
| 连接器 | kdocs（金山文档）已连接 |
| 台账 | 金山多维表《律师个人案件管理台账》一份（主表 4 案件总台账 + 子表 5/9/11/12/13/15/16；或先复制本技能作者的台账模板） |
| 授权 | 当前账号对该多维表有编辑权限 |

## 安装（AI 执行用）

把整个仓库放到 WorkBuddy 用户级技能目录：

```bash
# 1. 克隆仓库
git clone https://github.com/BluerAngala/case-ledger-intake.git ~/.workbuddy/skills/case-ledger-intake
# 2. 验证结构（必须含 SKILL.md）
ls ~/.workbuddy/skills/case-ledger-intake/SKILL.md
```

**无需手动配置**。首次使用时 AI 会自动执行「首次使用绑定」：
1. 检索关键词"律师个人案件管理台账"定位用户自己的多维表
2. 生成 `config.json`（含该用户的 file_id 与跳转链接，仅存本地）
3. 动态解析 schema（表/字段/视图映射），开始录入

> ⚠️ 仓库内**不含** config.json——它由每个用户首次运行时自动生成，是本地私有数据。

## 使用（触发词）

- "帮我录一个新案子" + 一段案情描述
- "这个案子现在到 X 阶段了，帮我理一下要记什么"
- "这是材料你看看" / "帮我整理一下"

## 目录结构

```
case-ledger-intake/
├── SKILL.md                    # 主规范（唯一事实源：流程/铁律/输出结构）
├── SHARE.md                    # 分发/分享安全指南（分发前必读）
├── lawyer-profile.md           # 律师画像（个人习惯，自行填写；提交到公开仓库前清空）
├── config.json                 # ⚠️ 本地自动生成，不入库（个人台账绑定）
└── references/
    ├── intake-guide.md         # 委托阶段指南（松散输入解析/提问顺序/时效推算）
    ├── filing-guide.md         # 立案阶段指南
    ├── hearing-guide.md        # 开庭阶段指南
    ├── preservation-guide.md   # 保全阶段指南
    ├── judgment-guide.md       # 判决阶段指南
    ├── execution-guide.md      # 执行阶段指南
    ├── closure-guide.md        # 结案阶段指南
    ├── ledger-schema.md        # 台账结构快照（业务参考，运行时以 schema 为准）
    └── subsidiary-tables.md    # 子表（期限提醒/收费/流程节点/人员）用法
```

## 隐私与安全

- 仓库内容已脱敏：不含任何真实 file_id、台账链接、当事人、案号、金额、律师姓名
- `config.json` 与 `lawyer-profile.md` 是**个人数据**，均不入库/提交前清空
- 若你 fork 或修改本技能后二次分发，遵守 `SHARE.md` 的清理清单
